Week 5 · September 21 – 25

Refactoring Piece & Building Game

Monday: hands-on. We refactor a real M1 Piece into the abstract base, write Knight together, and review M1 Boards. Wednesday: collections, generics, and exceptions, taught by building a Game that takes turns.

Milestones due: M2 — Monday, September 28 · M3 — Monday, October 5, both 11:59 PM

📋Topics covered

🌞 🌙
📅 Census is Monday, September 21. M1 is due that night. This week also puts the standard names on things you have already built: each session ends with a table of terms and the file in your repo where each one lives.

Monday — hands-on: refactoring Piece

  • Class vs object — what a compiler error is about.
  • Encapsulation — private hides, final freezes; access through accessors.
  • Constructors — where invariants are established; protected and super(...).
  • Packages — model, view, factory, engine, and which may import which.
  • Polymorphism from inside — one steppingMoves, run for a knight or a king.
  • Composition vs inheritance — the queen's eight directions; DRY as a judgement.
  • Object modeling — three questions for any class, applied in a code review of M1 Boards.

Wednesday — collections, generics, exceptions

  • The modeling process — nouns, buckets, one sentence per class; the third domain model of the semester.
  • Collections — List, Set, Map chosen by the question; interface on the left, implementation on the right.
  • Generics — reading List<Move> and Optional<Move>; raw types and the diamond.
  • Exceptions — null, boolean, Optional, or throw; checked vs unchecked; catch at the edge.
  • Game — turns with Color.opposite(), history as a stack, undo in two lines.

♟Milestone M3 — turns, moves, Game

M3 — opens Wednesday, September 23; due Monday, October 5 at 11:59 PM. A Game in a new engine package that lists the side to move's moves, plays one, refuses a bad one, and takes the last one back. Board gains apply and undo.

Wednesday's session settles the design. The rest is yours, in this order:

  1. Board.apply and Board.undo — two lines each, no checking.
  2. The accessors; history() returns a copy.
  3. legalMoves() — the loop over positionsOf(sideToMove). 6 red.
  4. findLegalMove — before play; the tests play through it. 5 red, 1 failing.
  5. play — the guard, apply, append, flip. 3 red.
  6. undoLastMove — pop, undo, flip back. Green: 42.
  7. Main plays e2e4 e7e5 and takes one back, then git add -A && git commit, git tag submit-m3 && git push origin main --tags
