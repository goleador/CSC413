Week 3 · September 7 – 11 · no meetings — see Week 4

OO Design: Board & Piece

The week the course stops being a Java review and starts being a design course. Every question this session has more than one answer that compiles — the work is choosing between them, and being able to say why.

Milestone due: M1 — Monday, September 21, 11:59 PM (opens Mon Sep 14)

📋Topics covered

🌞 🌙
  • One reason to change — the single-sentence test for what a class is responsible for.
  • Value vs. identity, revisited — why Piece is a class when Position was a record, and which requirement decides it.
  • Immutability by field — type and color are final; hasMoved is not.
  • Putting the answer with the data — PieceType carries its own letter, so no switch appears in the engine.
  • Composition — a board has 64 squares; it is not 64 squares.
  • Encapsulation, concretely — swap the array for bitboards and no other class changes.
  • Designing the interface first — what callers need, not what the array offers; and why remove returns the piece.
  • One flip, one place — [rank][file], and the upside-down array trap.
  • Packages — model, engine, view, and what each is allowed to know.

🚀Milestone M1 — the domain model

M1 — due Monday, September 21 at 11:59 PM (opens Monday September 14). Three classes — PieceType, Piece, Board — written from empty files, plus two view classes you are given. The full briefing is on the Week 4 page.

  1. Merge the milestone. git fetch upstream --tags then git merge m1 — the compile error that arrives names your first class.
  2. Build in order. PieceType → Piece → Board → toString() → Main. Each step makes the next one's failures readable.
  3. Go green — all of it. ./mvnw test → Tests run: 24, Failures: 0, Errors: 0, Skipped: 0. Twenty-four means M0b's eleven still pass; a milestone that breaks an earlier one is not done.
  4. Print a chessboard. Set up the starting position in Main and render it through the given TextBoardRenderer — the actual point of the milestone.
  5. Submit by tag. git tag submit-m1 && git push origin main --tags — then verify the tag shows on GitHub.

Graded by reading, not just by tests: Board's array stays private, and no model class prints, enforces a rule, or decides legality. If a method would fail the single-sentence test — "Board stores which piece is on which square" — it does not belong in M1.

Don't write movePiece or a canMove. That is M2, it arrives Wednesday September 16, and it is built with polymorphism rather than a switch. Code written now in the wrong shape gets deleted next week.
