Cohesion, Coupling, Separation of Concerns & SOLID

Monday: M2 already taught you this week's three words. We name them, then read the Game scaffold with them and find the one method that is not really about a game. 📋Topics covered

🌞 🌙
📅 Three milestones in flight. M2 is due Monday night, M3 stays open until October 5, and M4 opens Monday. M4 is a fifteen-minute refactor on top of a green M3; if M3 is still red, finish it first. Back on the syllabus calendar from here on.

Monday — cohesion, coupling, separation of concerns

  • What M2 did, named — seven files where there was one; the three reasons it was better.
  • Cohesion — one sentence, one reason to change, run on Knight, Board with M3's promotion switch, and the Game scaffold.
  • Coupling — the arrows in your repo today, drawn from your own import lines; the M3 promotion wrinkle as a coupling decision.
  • Separation of concerns — your four packages; facts about one piece are model, facts about the whole position are engine.
  • Reading the scaffold — which fields each method needs; the one method that would answer for any board and any colour, and where it should live.

Wednesday — SOLID

  • S — single responsibility: who would ask for the change? The scaffold's Game has two askers; M4 gives it one.
  • O — open/closed: the Archbishop; the one switch in PieceFactory, a violation on purpose.
  • L — Liskov: PieceMovementTest holds six classes to one promise; why your Pawn.attacks keeps it.
  • I — interface segregation: Game's public surface, and why one M4 method has no access modifier.
  • D — dependency inversion: Board holds Piece, never Knight; the Game(Board, Color) constructor.
  • Exercises — each job in M3 placed in its class before you write it; a god class taken apart, cut by cut.

♜Milestone M4 — MoveGenerator

M4 — opens Monday, September 28; due Monday, October 12 at 11:59 PM. A refactor: the generation loop moves out of Game into a new engine/MoveGenerator, and Game.legalMoves() becomes one line. The forty-two tests you have stay green throughout; six new ones arrive.

Monday's session settles why. The rest is yours, in this order:

  1. MoveGenerator.pseudoLegalMoves — cut the loop from Game, paste, sideToMove becomes color. Still 6 red.
  2. MoveGenerator.legalMoves — return pseudoLegalMoves(board, color); All six green.
  3. Game.legalMoves() — return MoveGenerator.legalMoves(board, sideToMove); and delete the loop. Still green: 48.
  4. git diff — the loop exists once; Main untouched. Then git add -A && git commit, git tag submit-m4 && git push origin main --tags

Graded by reading: the delegation is real, the loop is not copied, pseudoLegalMoves is still package-private, and nothing else in Game changed.
