Week 7 · October 5 – 9

Refactoring, Code Smells, Information Hiding & Clean Code

Monday: what refactoring is, seen through the change your Game is about to need. Wednesday: what a class promises, what it hides, and what a caller can break.

Milestones due: M3 — Monday, October 5 · M4 — Monday, October 12, both 11:59 PM

📋Topics covered

🌞 🌙
M4 preserves behavior. Wednesday adds nothing to M4's required implementation; it is about the boundaries your code already has.

Monday — refactoring and code smells

  • Why king safety cannot be added to Game.legalMoves() as it stands, worked out by questions.
  • Refactoring: structure changes, observable behavior does not. Which smells this story has, by name.
  • The IntelliJ moves M4 needs: Extract Method, Change Signature, Move.
  • Refactor first, then add the feature. M4 is the refactoring; M5 is the feature.

Wednesday — information hiding and clean code

  • Define encapsulation as control over what callers may know and do, not as private fields.
  • Define an invariant, and name the three a Game keeps.
  • Recognise leaked mutable state, and close it with a copy or a read-only view.
  • Tell objects what to do instead of manipulating them, and see the same boundary from methods up to packages.
