# OO Software Design Courses at Peer Institutions (vs. SFSU CSC 413), 2025–2026

Research date: 2026-10-04. Courses covered: SJSU CS 151, Cal Poly SLO CSC 203 (+ note on CSC 305), UBC CPSC 210, CSULB CECS 277, NC State CSC 216 (bonus public-university comparator). Sacramento State CSC 133 was investigated but its public materials are dead links (see Gaps).

## Key Question 1: Catalog description, prerequisites, language, topics, and schedule for each course

### Takeaway
Every verified peer course is taught in Java, like CSC 413. SJSU CS 151 and UBC CPSC 210 are the closest topical matches (OO design methodology, UML, design patterns, testing); Cal Poly CSC 203 covers the same material one year earlier in the curriculum (sophomore level, project-based); CSULB CECS 277 is a lower-division Java OO course whose public syllabi have gone offline.

### Cited Findings

**San Jose State — CS 151 "Object-Oriented Design" (3 units, upper-division, Java)**
- Catalog description (Fall 2026 syllabi): "Design of classes and interfaces. Object-oriented design methodologies and notations. Design patterns. Generics and reflection. Exception handling. Concurrent programming. Graphical user interface programming. Software engineering concepts and tools. Required team-based programming assignment." — [CS 151 Fall 2026 Zhong syllabus (PDF)](https://www.sjsu.edu/cs/docs/syllabi/fall26/CS_151_Fall_2026_Telvin_Zhong_Syllabus.pdf)
- Prerequisites: MATH 42, CS 46B, and (CS 48 or CS 49J if CS 46B was not in Java), each C- or better; restricted to CS/Math/SE/Data Science majors or instructor consent. 3 units, in person, Fall 2026 (8/19–12/07/2026). — [Zhong syllabus](https://www.sjsu.edu/cs/docs/syllabi/fall26/CS_151_Fall_2026_Telvin_Zhong_Syllabus.pdf)
- Course goals (Zhong section): systematic OO design methodology; use cases, noun/verb analysis, CRC cards; interpret/produce UML diagrams; use design patterns; "Practice SOLID design principles"; advanced Java (interfaces, abstract/nested classes, generics, lambdas, serialization, exceptions, threads); JavaFX GUI. — [Zhong syllabus](https://www.sjsu.edu/cs/docs/syllabi/fall26/CS_151_Fall_2026_Telvin_Zhong_Syllabus.pdf)
- No required textbook; supplemental reading is Cay Horstmann, "Object-Oriented Design & Patterns," 3rd ed. (Horstmann taught CS 151 at SJSU; his tradition persists in current sections). — [Zhong syllabus](https://www.sjsu.edu/cs/docs/syllabi/fall26/CS_151_Fall_2026_Telvin_Zhong_Syllabus.pdf); [Chen syllabus](https://www.sjsu.edu/cs/docs/syllabi/fall26/Object_Oriented_Design_CS_151_Fall_2026_03_Eric_Chen.pdf)
- Week-by-week schedule (Fall 2026, Chen section 03): Wk 0 intro; Wks 1–2 Java OOP basics; Wk 3 OOP basics + UML; Wks 4–6 OO design patterns; Wk 7 project start discussion; Wk 8 midterm; Wk 9 advanced Java (exceptions, generics); Wk 10 advanced design patterns (Comparator/sorting, Iterator/built-in data structures); Wk 11 project checkpoint + multithreading; Wk 12 serialization (JSON, Protobuf); Wk 13 reflection + project final checkpoint; Wk 14 Java performance optimization; Wk 15 Java unit testing; Wk 16 review + project due. — [CS 151 Fall 2026 Chen syllabus (PDF)](https://www.sjsu.edu/cs/docs/syllabi/fall26/Object_Oriented_Design_CS_151_Fall_2026_03_Eric_Chen.pdf)
- Historical anchor: Horstmann's own Fall 2016 CS 151 covered UML class + sequence diagrams, use cases/CRC cards, frameworks, and six named patterns: Composite, Decorator, Iterator, Strategy, Template Method, Observer. — [Horstmann SJSU CS 151 Fall 2016](https://horstmann.com/sjsu/fall2016/cs151/gs.html)
- Prior Java knowledge is not assumed in current sections ("Prior Java knowledge is not a prerequisite for this course"). — [Zhong syllabus](https://www.sjsu.edu/cs/docs/syllabi/fall26/CS_151_Fall_2026_Telvin_Zhong_Syllabus.pdf)

- Catalog description: "Object-oriented programming and design with applications to project construction. Introduction to class design, interfaces, inheritance, generics, exceptions, streams, and testing." 4 units, 3 lectures + 1 lab; prerequisite CPE/CSC 202 with C- or better. — [Coursicle: Cal Poly CSC 203](https://www.coursicle.com/calpoly/courses/CSC/203/)
- Public syllabus (Christopher Siu, Summer 2019 — most recent public PDF found): topics are introductory Java; classes, objects, interfaces; inheritance, abstraction, composition; subtypes and generics; UML diagrams; design patterns; exception handling; introductory software engineering. Supplementary texts: Horstmann "Core Java Vol. I" and Gamma et al. "Design Patterns" (GoF). — [CSC 203 syllabus, users.csc.calpoly.edu/~cesiu](https://users.csc.calpoly.edu/~cesiu/csc203/syllabus.pdf)

- Renumbering caveat: Cal Poly's 2026–2028 catalog has moved to 4-digit course numbers and no longer lists CSC 203/305 under those numbers; CSC 3100 "Software Engineering" (formerly CSC 308, prereq CPE/CSC 202 or CSC 2001) is the listed design-adjacent successor course. — [Cal Poly catalog, CSC courses](https://catalog.calpoly.edu/courses/csc/)

**UBC — CPSC_V 210 "Software Construction" (4 credits, second-year, Java)**
- Catalog: "Design, development, and analysis of robust software components. Topics such as software design, computational models, data structures, debugging, and testing." 4 credits, [3-2-0] lecture-lab; prerequisite: one of CPSC 107 or CPSC 110. — [UBC Vancouver Academic Calendar, CPSC_V 210](https://vancouver.calendar.ubc.ca/course-descriptions/courses/cpscv-210)
- Six published modules with learning goals (2023W official section page, instructor Paul Carter): (1) Data Abstraction — specify/use/test/implement a data abstraction in Java; (2) Control Flow Models — inter-/intra-method control flow diagrams; (3) Type Hierarchies, Polymorphism and Dispatching — trace polymorphic execution, type substitutability; (4) Robust Data Abstractions — exceptions; (5) Object-Oriented Design — record a design as a UML class diagram, extract UML sequence diagrams from code, express a UML class diagram as a Java program, use the Java Collections Framework; (6) Design Patterns — apply Composite, Observer, and Iterator. — [cs.ubc.ca CPSC 210 102 2023W](https://www.cs.ubc.ca/course-section/cpsc-210-102-2023w)
- The companion UBCx edX MOOC pair (SoftConst1x "Data Abstraction", SoftConst2x "Object-Oriented Design", by Elisa Baniassad and Gail Murphy) mirrors the course. SoftConst1x video units: codebase navigation, call graphs, debugging (4 parts), data abstraction and specifications (requires/modifies/effects), JUnit (@Test, @Before, asserts) and test design, interfaces & subtyping (actual vs. apparent types), extending classes/overriding, abstract classes. SoftConst2x units: designing robust classes (exception hierarchies, testing exceptions, assertions), extracting OO design (class hierarchies, associations, sequence diagrams), implementing OO design, design principles (Single Responsibility, coupling, Liskov Substitution, refactoring), design patterns (Composite, Observer, Iterator). — [UBC Software Construction video index](https://www.cs.ubc.ca/~ebani/SoftwareConstructionVideos.html); [UBCx SoftConst2x listing (mirror)](https://github.com/nasirxo/Courses-/blob/master/UBCx-Software-Construction-OOP-SoftConst2x/README.md)
- Active in 2025W/2026: multiple lecture sections plus 2-hour weekly labs (e.g., 2025 section 201 MWF 10–11 with Norman Hutchinson; lab L2J Wed 1–3). — [UBC course sections: Software Construction 2025 sec 201](https://courses.students.ubc.ca/courses/software-construction/software-construction-2025-sec-201); [lab section L2J](https://courses.students.ubc.ca/courses/software-construction/software-construction-2025-sec-l2j-0)

**NC State — CSC 216 (+ CSC 217 lab), Spring 2026 — bonus public-university comparator**
- Fully public day-by-day Spring 2026 schedule, Java: Wk 1 OO review, composition, software testing & the debugger; Wk 2 SE best practices, Java Collections, inheritance, polymorphism; Wk 3 abstract classes, interfaces, exceptions, design patterns, finite state machines; Wk 4 FSMs with the State pattern, Exam 1, SDLC/task planning; Wks 5–8 generic ArrayLists, linked nodes, LinkedLists, stacks, queues, Exam 2; Wks 9–10 iterators, recursion, project work days; final weeks searching, BSTs, sorting. 11 labs (installfest, pair programming, V&V, collections, design, debugging, FSMs, data structures, iterators, recursion); guided projects plus 2 major projects each in two phases (P1P1/P1P2, P2P1/P2P2). — [CSC 216-002 Spring 2026 schedule](https://courses.csc.ncsu.edu/csc216/schedule/S26_CSC216-002_Schedule)

### Inferences
- SJSU CS 151 is the single closest CSU analog to CSC 413: same language, same Horstmann lineage (CSC 413 historically used Horstmann-style OO design content), near-identical topic spine (UML -> patterns -> exceptions/generics -> threading -> unit testing), compressed GUI/concurrency emphasis that CSC 413 replaces with refactoring/SOLID/maintenance depth.
- CSC 413's placement is unusual: peers put this material in year 2 (Cal Poly 203, UBC 210, NCSU 216, CSULB 277); only SJSU CS 151 sits at the junior level like CSC 413.
- UBC CPSC 210's module list overlaps CSC 413 on UML, SOLID-adjacent principles (SRP, Liskov, coupling), refactoring, JUnit, and debugging, but spends more time on specification/data abstraction and less on patterns breadth (3 patterns vs. CSC 413's 6).

### Gaps
- Cal Poly CSC 305 "Individual Software Design and Development": not found in the current (2026–2028, renumbered) catalog and no public syllabus located; could not verify its current number or status.
- Sacramento State CSC 133 (Object-Oriented Computer Graphics Programming, uses Horstmann OODP as optional text per search snippets): the official course-proposal PDF at csus.edu now returns a 404 page; no reliable current syllabus found, so it is excluded from the detailed findings.
- CSU Fullerton CPSC 223J/362 and SDSU CS 310/160: not investigated in depth (budget spent on courses with stronger public materials); no public syllabi surfaced in the searches run.
- No public week-by-week schedule exists for UBC CPSC 210 (schedule lives in Canvas/GitHub-based course site behind CWL login); the module list above is the official public substitute.

## Key Question 2: Anchoring projects (semester-long vs. several; team vs. individual)

### Takeaway
No peer course matches CSC 413's single 14-milestone individual chess engine. The closest structural analog is Cal Poly CSC 203's individual quarter-long project built as 5 cumulative milestone projects (40% of grade); SJSU and UBC use one term project (team of 2–4 at SJSU; individual at UBC) that starts mid-semester rather than anchoring the whole course.

### Cited Findings
- Cal Poly CSC 203 (Siu, Summer 2019): "You will be assigned five projects that, together, form one quarter-long project," completed individually, submitted via GitHub Classroom, manually graded on functionality and code quality (efficiency, style, decomposition, documentation); students must average >=50% on the project to earn a C or better; plus 10 collaborative autograded labs. — [CSC 203 syllabus](https://users.csc.calpoly.edu/~cesiu/csc203/syllabus.pdf)
- SJSU CS 151 (Zhong, F2026): three projects in groups of 3–4, hosted in private GitHub repos, together "around half of your grade" (10% + 12% + 13%); graded on repo state at the deadline. — [Zhong syllabus](https://www.sjsu.edu/cs/docs/syllabi/fall26/CS_151_Fall_2026_Telvin_Zhong_Syllabus.pdf)
- SJSU CS 151 (Chen, F2026): one term project, "recommended done as a group project with 2–3 students," starting week 7 with checkpoints in weeks 11 and 13 and delivery in week 16. — [Chen syllabus](https://www.sjsu.edu/cs/docs/syllabi/fall26/Object_Oriented_Design_CS_151_Fall_2026_03_Eric_Chen.pdf)
- SJSU CS 151 (Horstmann, F2016): individual programming assignments (25%) plus a team project (25%) in groups of 3–4 on an instructor-selected topic with documented individual contributions. — [Horstmann CS 151 F2016](https://horstmann.com/sjsu/fall2016/cs151/gs.html)
- UBC CPSC 210: anchored by an individual "personal project" built across the term in Java; a student project writeup (Libralist) documents the stack as Java with a Swing GUI and the JSON library for persistence, with JUnit for testing. — [Libralist CPSC 210 project writeup](https://noon-bull-22f.notion.site/Libralist-5751953459704e21be0c639efad00ee1) (search-snippet level; page body not retrievable)
- UBC CPSC 210 labs: weekly 2-hour scheduled lab sections accompany lectures (2025W listings). — [UBC course sections](https://courses.students.ubc.ca/courses/software-construction/software-construction-2025-sec-l2j-0)
- NC State CSC 216 (S2026): several guided projects plus two major projects, each delivered in two phases, alongside 11 weekly labs — multiple medium projects rather than one semester artifact. — [CSC 216 S26 schedule](https://courses.csc.ncsu.edu/csc216/schedule/S26_CSC216-002_Schedule)
- CSULB CECS 277 (2014–2019 offerings): graded via assignments + exams only (no large project component in the published breakdowns). — [CECS 277 syllabi (dead links, search-index content)](https://home.csulb.edu/~pnguyen/cecs277/syllabus/cecs277syllabusfa14.html)

### Inferences
- CSC 413's design is distinctive on three axes simultaneously: (a) one continuous artifact for all 16 weeks, (b) 14 fine-grained milestones (peers use 2–5), and (c) a design-defense final. Cal Poly 203 shares (a)+(c, via manual code-quality grading) at coarser granularity; UBC 210 shares (a) individually but with ~4 phases; SJSU is team-based and starts the project only at midterm.
- The chess domain is also unusual; peers use instructor-selected or student-chosen application domains (UBC lets students pick their personal project domain).

### Gaps
- The canonical Cal Poly CSC 203 project domain (commonly reported by students as a "Virtual World" simulation refactoring project) could not be confirmed from any citable primary source; searches returned no official project spec.
- UBC CPSC 210's official phase-by-phase project spec (Phase 1 console app -> Phase 2 JSON persistence -> Phase 3 Swing GUI -> Phase 4 UML + event logging, as commonly described in student READMEs) is behind the course's authenticated site; I could not cite an official document, so the phase structure should not be stated as verified fact beyond "individual term project, Java/Swing/JSON/JUnit."

## Key Question 3: Coverage of the CSC 413 topic set (SOLID, refactoring, design patterns, UML, MVC, JUnit, Git/Maven tooling)

### Takeaway
UML, design patterns, JUnit-style testing, and exceptions are universal across peers; SOLID is named explicitly only at SJSU (and partially at UBC via SRP/Liskov); refactoring is explicit only at UBC; MVC, Maven, and technical-debt/maintenance content appear in none of the public peer syllabi — these are CSC 413 differentiators.

### Cited Findings
- SOLID: SJSU CS 151 (Zhong) lists "Practice SOLID design principles" as a course goal — [Zhong syllabus](https://www.sjsu.edu/cs/docs/syllabi/fall26/CS_151_Fall_2026_Telvin_Zhong_Syllabus.pdf); UBC CPSC 210/SoftConst2x teaches Single Responsibility, coupling, and Liskov Substitution (not the full SOLID five) — [UBC video index](https://www.cs.ubc.ca/~ebani/SoftwareConstructionVideos.html)
- Refactoring: explicitly a unit in UBC SoftConst2x "Design Principles" module — [UBC video index](https://www.cs.ubc.ca/~ebani/SoftwareConstructionVideos.html); not mentioned in SJSU, Cal Poly, CSULB, or NCSU public syllabi/schedules reviewed.
- Design patterns: SJSU — 3+ weeks of "OO Design Patterns" plus "Advanced Design Patterns (Comparator/Sorting, Iterator)" ([Chen schedule](https://www.sjsu.edu/cs/docs/syllabi/fall26/Object_Oriented_Design_CS_151_Fall_2026_03_Eric_Chen.pdf)); Horstmann-era list: Composite, Decorator, Iterator, Strategy, Template Method, Observer ([Horstmann F2016](https://horstmann.com/sjsu/fall2016/cs151/gs.html)); UBC — Composite, Observer, Iterator ([cs.ubc.ca 2023W](https://www.cs.ubc.ca/course-section/cpsc-210-102-2023w)); Cal Poly 203 — "Design patterns" topic with GoF as supplementary text ([Siu syllabus](https://users.csc.calpoly.edu/~cesiu/csc203/syllabus.pdf)); NCSU 216 — "Design and Patterns" lecture plus "FSMs and the State Pattern" ([S26 schedule](https://courses.csc.ncsu.edu/csc216/schedule/S26_CSC216-002_Schedule)). CSC 413's Factory/Builder/Command/State/Strategy/Observer set overlaps most with NCSU (State) and SJSU/Horstmann (Strategy, Observer).
- UML: SJSU course goal + week 3 ([Chen syllabus](https://www.sjsu.edu/cs/docs/syllabi/fall26/Object_Oriented_Design_CS_151_Fall_2026_03_Eric_Chen.pdf)); UBC class + sequence diagrams, both directions (extract from code, implement from diagram) ([cs.ubc.ca 2023W](https://www.cs.ubc.ca/course-section/cpsc-210-102-2023w)); Cal Poly topic list ([Siu syllabus](https://users.csc.calpoly.edu/~cesiu/csc203/syllabus.pdf)). CSC 413's component/state diagrams go beyond all peers' published class+sequence coverage.
- MVC / layered architecture: not mentioned in any reviewed public syllabus (SJSU does JavaFX/GUI, UBC does Swing GUI in the project, where MVC is implicit but unpublished).
- JUnit/unit testing: UBC has the deepest published treatment (JUnit mechanics, test design, "bugs in tests" debugging unit, testing exceptions) — [UBC video index](https://www.cs.ubc.ca/~ebani/SoftwareConstructionVideos.html); SJSU schedules "Java Unit Test" in week 15 ([Chen syllabus](https://www.sjsu.edu/cs/docs/syllabi/fall26/Object_Oriented_Design_CS_151_Fall_2026_03_Eric_Chen.pdf)); Cal Poly lists "testing" in the catalog description ([Coursicle](https://www.coursicle.com/calpoly/courses/CSC/203/)); NCSU opens with "Software Testing & the Debugger" in week 1 ([S26 schedule](https://courses.csc.ncsu.edu/csc216/schedule/S26_CSC216-002_Schedule)).
- Git/GitHub tooling: SJSU hosts projects in private GitHub repos and recommends git familiarity ([Zhong syllabus](https://www.sjsu.edu/cs/docs/syllabi/fall26/CS_151_Fall_2026_Telvin_Zhong_Syllabus.pdf)); Cal Poly submits labs and projects via GitHub Classroom with scheduled autograding ([Siu syllabus](https://users.csc.calpoly.edu/~cesiu/csc203/syllabus.pdf)). Maven (or any build tool) appears in no peer syllabus reviewed.
- Debugging: UBC devotes four dedicated video units to debugging ([UBC video index](https://www.cs.ubc.ca/~ebani/SoftwareConstructionVideos.html)); NCSU has a debugger lecture + lab ([S26 schedule](https://courses.csc.ncsu.edu/csc216/schedule/S26_CSC216-002_Schedule)).
- Concurrency/GUI (peer topics CSC 413 does NOT emphasize): SJSU covers multithreading, serialization (JSON/Protobuf), reflection, performance/GC, JavaFX ([Chen](https://www.sjsu.edu/cs/docs/syllabi/fall26/Object_Oriented_Design_CS_151_Fall_2026_03_Eric_Chen.pdf), [Zhong](https://www.sjsu.edu/cs/docs/syllabi/fall26/CS_151_Fall_2026_Telvin_Zhong_Syllabus.pdf)); CSULB covered multithreading and disk I/O ([CECS 277 catalog text](https://home.csulb.edu/~pnguyen/cecs277/syllabus/cecs277syllabusfa14.html)).

### Inferences
- CSC 413's refactoring/code-smells/information-hiding/technical-debt block is its clearest curricular differentiator; among peers only UBC publicly names refactoring, and none names code smells or technical debt.
- Conversely, CSC 413 omits the GUI + concurrency block that SJSU/CSULB treat as core; a comparison document should present this as a deliberate trade (design depth + maintenance vs. Java platform breadth).
- Peer courses treat Git as infrastructure (submission mechanism) rather than a taught topic; CSC 413's explicit Git/GitHub/Maven tooling week has no published peer equivalent.

### Gaps
- Coverage judgments are limited to published syllabi/schedules; lecture-level content (e.g., whether SJSU mentions MVC during JavaFX weeks, or whether Cal Poly labs use Maven/Gradle) is not publicly documented.

## Key Question 4: Grading breakdowns

### Takeaway
Peer grading splits cluster around 50–65% exams / 25–50% project+assignments at SJSU and CSULB, while Cal Poly weights the project at 40% with a project-passing gate; published peer courses rely on 2–3 exams, far more exam-heavy than a milestone-driven project course.

### Cited Findings
- SJSU CS 151, Fall 2026, Zhong section: Midterm 30%, Final 35%, Project 1 10%, Project 2 12%, Project 3 13% (projects = 35%; exams = 65%); fixed scale starting at 97 = A+, no rounding, extra-credit opportunities. — [Zhong syllabus](https://www.sjsu.edu/cs/docs/syllabi/fall26/CS_151_Fall_2026_Telvin_Zhong_Syllabus.pdf)
- SJSU CS 151, Fall 2026, Chen section: Assignments 30% (6 x 5%), Quizzes 20% (~10 x 2%), Project 15%, Midterm 15%, Final 20%. — [Chen syllabus](https://www.sjsu.edu/cs/docs/syllabi/fall26/Object_Oriented_Design_CS_151_Fall_2026_03_Eric_Chen.pdf)
- SJSU CS 151, Fall 2016, Horstmann: Exams 45%, programming assignments 25%, team project 25%, participation 5%. — [Horstmann F2016](https://horstmann.com/sjsu/fall2016/cs151/gs.html)
- Cal Poly CSC 203, Summer 2019, Siu: Labs (10) 10%; Quarter-Long Project 40% (4 milestones 28% + final submission 12%); 2 midterms 20%; final exam 30%; must average >=50% on the project to receive a C or better; A at 92/B 82/C 72. — [Siu syllabus](https://users.csc.calpoly.edu/~cesiu/csc203/syllabus.pdf)
- CSULB CECS 277: Fall 2014 — 2 midterms 46%, assignments 24%, final 30%; Fall 2018/2019 — 2 midterms 42%, 3 quizzes 6%, assignments 22%, final 30%. — [CECS 277 syllabi (dead links; search-index content, 2014–2019)](https://home.csulb.edu/~pnguyen/cecs277/syllabus/cecs277syllabusfa19.html)

### Inferences
- Where CSC 413 lets 14 milestones + a design defense carry the grade, every peer with published numbers caps project weight at 40% and keeps >=50% on exams/quizzes; Cal Poly's "must pass the project" gate is the nearest peer mechanism to CSC 413's project-centric accountability.

### Gaps
- UBC CPSC 210 grading breakdown is not public (Canvas-gated); no reliable 2023–2026 source found.
- NC State CSC 216 grading weights were not on the public schedule page; the syllabus page would need a separate fetch.
- Current (2023–2026) CSULB CECS 277 grading is unpublished; only 2014–2019 breakdowns exist, from now-dead pages.
