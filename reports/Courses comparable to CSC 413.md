# Few Courses Rival the Chess Spine

No surveyed course — across five flagship universities, five peer public universities, two European/structural analogs, and the major MOOC platforms — replicates CSC 413's combination of one Java artifact built in 14 fine-grained milestones across all 16 weeks, a perft/JUnit correctness milestone, and an individual design defense. The two genuinely comparable courses are **CMU 17-214 "Principles of Software Construction"** (Spring 2026: Java + TypeScript, UML, patterns, refactoring, a Santorini board game built in milestones with peer design review ([CMU s2026](https://cmu-17-214.github.io/s2026/))) and **EPFL CS-108 "Practice of Object-Oriented Programming"** (one board/strategy game built in 12 numbered weekly stages, guided-then-released, running annually since 2017 ([cs108.epfl.ch](https://cs108.epfl.ch/))). Among CSUs, **SJSU CS 151 "Object-Oriented Design"** is the closest sibling — same language, same Horstmann lineage, SOLID named as a course goal — but its project is team-based and starts only at week 7 ([Zhong syllabus](https://www.sjsu.edu/cs/docs/syllabi/fall26/CS_151_Fall_2026_Telvin_Zhong_Syllabus.pdf)). The former gold-standard flagship comparisons have drifted away: MIT 6.102 and UW CSE 331 both moved from Java to TypeScript and toward specification/reasoning content, and Stanford CS 108 appears dormant. Online, the University of Alberta's four-course "Software Design and Architecture" Coursera specialization is the only MOOC that treats design — UML, patterns, code smells, MVC — as the subject rather than programming ([Coursera](https://www.coursera.org/specializations/software-design-architecture)). Three topics turn out to be CSC 413 differentiators almost nowhere else taught by name: the refactoring/code-smells/technical-debt block, MVC as an explicit architecture unit, and Git/Maven/IntelliJ tooling as taught content rather than assumed infrastructure.

## CMU and EPFL run the same pedagogy: one game, staged milestones, design review

CMU 17-214 (Spring 2026, "Objects, Design, and Concurrency") matches CSC 413 nearly topic-for-topic and uses the same core device. Its lecture arc runs Intro/IDEs/build systems/CI → OO basics and encapsulation → **OO Analysis and UML** → responsibility assignment → inheritance and delegation → **design patterns** → **refactoring and anti-patterns** → specifications/unit testing/exceptions → test design and testability, before a back half CSC 413 does not attempt: four to five concurrency lectures, API design, supply-chain security, distributed systems, DevOps, and static/dynamic analysis ([CMU s2026](https://cmu-17-214.github.io/s2026/)). Its anchor is **HW2: the Santorini board game in three milestones (intro design, peer design review, final design)**, later extended in HW6's two UI milestones (user interface, then god-card variants) — build the game core, review the design, refactor (HW4 is explicitly "Design and Testability Refactoring"), extend with a UI and rule variants. That is CSC 413's M1→M6→M9→M12 arc compressed into six homeworks. Grading is also comparable: CMU's assignments 50% + labs 10% versus exams 30% sits next to CSC 413's project 40% + assignments 15% versus exams 35%. Required texts are Larman's *Applying UML and Patterns* and Bloch's *Effective Java* ([CMU s2026](https://cmu-17-214.github.io/s2026/)). One critical caveat for any ongoing comparison: the **Fall 2026 offering is retitled "Agentic Software Development,"** reorganizing the same design skeleton (testing → design → modularity → refactoring → patterns) around AI-agent-assisted engineering, with assignments like "Refactor and Critique an Unfamiliar Codebase" and "Operate What You Built" ([CMU f2026](https://cmu-17-214.github.io/f2026/)). Spring 2026 may be the last run of the classic form.

EPFL CS-108 is the strongest *structural* match anywhere. Students build one electronic board game — a new game each year; 2024's was **ChaCuN**, a 2–5 player tile-placement game — in **12 numbered weekly stages across three guidance phases: stages 1–6 heavily guided, 7–11 less guided, stage 12 optional and nearly unrestricted** ([CS-108 2024 project intro](https://cs108.epfl.ch/archive/24/p/00_introduction.html)). The stage sequence mirrors CSC 413's milestone logic: domain objects first (tiles, areas, partitions), then game board and game state, then scoring/messages, then JavaFX GUI stages, then networking, then final integration. Its grading split is a concrete model worth study: of 500 total points, the project carries 300 — **90 points of weekly autograded "tested submissions" (stages 2–6), 190 points across two human code-reviewed consolidated submissions judged on "efficiency, conciseness, and elegance,"** plus a 20-point final test — alongside a 75-point midterm and 125-point final ([CS-108 2024 project intro](https://cs108.epfl.ch/archive/24/p/00_introduction.html)). Teams are capped at two. The parallel to CSC 413 is almost exact — M0–M6 ≈ the guided phase, M7–M12 ≈ the semi-guided phase, M13's integration-and-defense ≈ the free phase — with two differences: EPFL rotates the game annually where CSC 413 fixes chess, and EPFL substitutes code review plus exams where CSC 413 holds an individual oral design defense.

Northeastern CS 3500 "Object-Oriented Design" belongs in this family but uses two shorter arcs instead of one long one: a "Playing with Cards" warm-up (Assignments 2–4), then a four-part spreadsheet project (Fall 2019's "Beyond gOOD," parts due 10/31, 11/14, 11/26, 12/04) capped by a capstone extending the work ([CS 3500 f19](https://course.ccs.neu.edu/cs3500f19/)). Its Fall 2023 lecture sequencing is strikingly CSC 413-like — OO fundamentals → **MVC and Builder** → controllers and invariants → **Command pattern**, inheritance vs. composition → Swing GUI → **Observer/Strategy/Decorator/Adapter** — with homework at 60% of the grade and next-day written self-evaluations as the reflection mechanism ([CS 3500 f23](https://course.ccs.neu.edu/cs3500f23/)). Its most distinctive assessment idea, with no CSC 413 equivalent, is the capstone-against-foreign-code move: students extend a codebase they did not write.

## SJSU CS 151 is the CSU sibling; peers teach this material a year earlier

Every verified peer-university course is taught in Java, and SJSU CS 151 (upper-division, 3 units) is the closest match in both level and content: course goals include systematic OO design methodology, use cases/CRC cards, UML, design patterns, **"Practice SOLID design principles,"** advanced Java, and JavaFX GUI programming, with no required textbook but Horstmann's *Object-Oriented Design & Patterns* as the supplemental reading ([Zhong syllabus](https://www.sjsu.edu/cs/docs/syllabi/fall26/CS_151_Fall_2026_Telvin_Zhong_Syllabus.pdf)). SJSU is the only peer besides CSC 413 that names SOLID. The schedule contrast is instructive, though. The Chen section's Fall 2026 week-by-week runs: weeks 1–3 Java OOP basics + UML; **weeks 4–6 design patterns** (three weeks earlier than CSC 413's week 9); **week 7 project start**; week 8 midterm; weeks 9–14 advanced Java (exceptions/generics, multithreading, serialization, reflection, performance); **week 15 unit testing**; week 16 project due ([Chen syllabus](https://www.sjsu.edu/cs/docs/syllabi/fall26/Object_Oriented_Design_CS_151_Fall_2026_03_Eric_Chen.pdf)). Where CSC 413 spends weeks 6–7 on cohesion/coupling/SOLID and refactoring/code smells, SJSU spends the equivalent weeks on Java platform breadth (threads, JSON/Protobuf serialization, reflection, GC) — a deliberate trade of design depth for platform coverage. Project structure diverges most: Zhong's section runs three team projects (groups of 3–4, private GitHub repos, 35% combined) against a 65% exam weight; Chen's runs one team project at just 15%, starting week 7 with checkpoints at weeks 11 and 13 ([Zhong](https://www.sjsu.edu/cs/docs/syllabi/fall26/CS_151_Fall_2026_Telvin_Zhong_Syllabus.pdf), [Chen](https://www.sjsu.edu/cs/docs/syllabi/fall26/Object_Oriented_Design_CS_151_Fall_2026_03_Eric_Chen.pdf)). No peer section lets a project anchor week one the way M0 does.

The other peers place this material a full year earlier. **Cal Poly CSC 203** ("Project-Based Object-Oriented Programming and Design," sophomore level, 4 units) is the closest project-structure analog: five individual projects "that, together, form one quarter-long project," submitted via GitHub Classroom, manually graded on code quality, weighted at 40% — identical to CSC 413's project weight — with a gate requiring ≥50% on the project to earn a C ([Siu syllabus](https://users.csc.calpoly.edu/~cesiu/csc203/syllabus.pdf)). That project-passing gate is the nearest peer mechanism to CSC 413's milestone-driven accountability. **UBC CPSC 210** (second-year, 4 credits) anchors on an individual term project in Java/Swing/JUnit and publishes six modules that overlap CSC 413 on UML class and sequence diagrams (in both directions — extract from code, implement from diagram), exceptions, JUnit test design, debugging (four dedicated video units), and a design-principles unit covering Single Responsibility, coupling, Liskov Substitution, and **refactoring** — but only three patterns (Composite, Observer, Iterator) against CSC 413's six ([cs.ubc.ca 2023W](https://www.cs.ubc.ca/course-section/cpsc-210-102-2023w); [UBC video index](https://www.cs.ubc.ca/~ebani/SoftwareConstructionVideos.html)). **NC State CSC 216** publishes a fully public Spring 2026 day-by-day schedule and teaches the State pattern via finite-state machines in weeks 3–4, but is half a data-structures course with two two-phase projects rather than one semester artifact ([CSC 216 S26 schedule](https://courses.csc.ncsu.edu/csc216/schedule/S26_CSC216-002_Schedule)). CSULB CECS 277 is a lower-division Java OO course graded on assignments and exams only, with its public syllabi offline since roughly 2019. Across all published peer grading schemes, exams carry 50–65% of the grade; CSC 413's 35% exam weight and 40% single-project weight are outliers in the peer set.

## The flagships have moved off Java and away from design-pattern pedagogy

The courses an instructor would reflexively cite as comparisons mostly no longer compare. **MIT 6.102 Software Construction** (Spring 2025) is now taught in **TypeScript**, centered on specifications, abstract data types, abstraction functions/rep invariants, testing, and a large concurrency/async arc — with no UML, no named GoF patterns unit, no SOLID or refactoring vocabulary, and the team project (the "Star Battle" puzzle game, 3-person teams) worth only 10% of the grade against 45% for five individual problem sets ([MIT 6.102 sp25](https://web.mit.edu/6.102/www/sp25/); [general info](https://web.mit.edu/6.102/www/sp25/general/)). Its alpha → code review → beta problem-set cycle is functionally a refactoring exercise, and that iteration discipline is the most borrowable idea in the course, but the Java-era version survives only as the archived 6.005 on OpenCourseWare ([OCW 6.005](https://ocw.mit.edu/courses/6-005-software-construction-spring-2016/)). **UW CSE 331** has been redesigned even further afield: Spring 2025 is a TypeScript/React course on formal reasoning about correctness — Floyd logic, structural induction, proofs — with **no project at all** (75% individual homework, 24% final, no midterm) and a single design-patterns lecture closing the quarter ([CSE 331 25sp syllabus](https://courses.cs.washington.edu/courses/cse331/25sp/info/); [calendar](https://courses.cs.washington.edu/courses/cse331/25sp/calendar/calendar.html)). The 2023-era Java CSE 331 was much closer; the archive at [23au](https://courses.cs.washington.edu/courses/cse331/23au/index.html) shows the old form. **Stanford CS 108** — whose catalog line "Software design and construction in the context of large OOP libraries. Taught in Java" reads like CSC 413's own description — appears dormant: the bulletin shows no scheduled sections and the public course site is an explicitly unmaintained archive, with the last confirmed teaching evidence from Winter 2023–24 ([Stanford Bulletin](https://bulletin.stanford.edu/courses/1056501); [CS 108 site](http://web.stanford.edu/class/cs108/)). **Berkeley CS 61B** overlaps only at the front end — five weeks of Java OO (inheritance, interfaces, polymorphism, comparators) before pivoting to data structures, with software-engineering lectures as optional sidebars and exams at ~53% of points ([CS 61B fa25](https://fa25.datastructur.es/); [policies](https://fa25.datastructur.es/policies/)). The net effect: among active flagship offerings, only CMU still teaches UML, named patterns, and refactoring as graded core — and only CMU still does so in Java.

## Online, only Alberta teaches design; nothing online teaches the toolchain

The University of Alberta's **"Software Design and Architecture" specialization** (Coursera, 4 courses × 4 weeks ≈ 16 weeks at ~10 hrs/week, Java, 107k enrolled, 4.6/5) is the one MOOC whose subject is design rather than programming. Course 1 covers CRC analysis, the four OO principles, UML class diagrams translated to Java, and cohesion/coupling tradeoffs; Course 2 covers design patterns, open-closed and dependency-inversion principles, **code smells and anti-pattern refactoring, and MVC**; Course 3 covers layered/n-tier architecture and four more UML diagram types; Course 4 covers SOA/REST/microservices; and a Java Android app evolves as the capstone through all four courses ([Coursera](https://www.coursera.org/specializations/software-design-architecture)). That maps to roughly CSC 413 weeks 4–11 — but with no Git/Maven/IntelliJ content, no named JUnit practice, and no technical-debt unit. The Duke and UCSD Java specializations are CS1/CS2-level: Duke's only brush with CSC 413 territory is its fourth course (interfaces, abstract classes, exceptions), and neither reaches UML, SOLID, patterns, or refactoring by name ([Duke spec](https://www.coursera.org/specializations/java-programming); [UCSD spec](https://www.coursera.org/specializations/object-oriented-programming)). UBC's edX pair (SoftConst1x/2x, the MOOC mirror of CPSC 210 and the best structural match for CSC 413's first half) appears retired — the MicroMasters program page and both course pages return 404, with certificates issued only through August 2025 ([edX certificate record](https://courses.edx.org/certificates/33501999a53c43ef8016f9a6967a389c)). For the refactoring/smells/patterns/SOLID slice specifically, **refactoring.guru** covers exactly that and nothing else: 21 code smells and 66 refactoring techniques (~$40 course) plus 22 GoF patterns and SOLID in the companion ebook, with Java examples but no schedule, projects, or assessment ([refactoring.guru course](https://refactoring.guru/refactoring/course)). Across every online offering surveyed, two absences are consistent: no MOOC uses a game — let alone chess — as its running project, and the IntelliJ/Git/Maven toolchain is taught nowhere.

## Set against CSC 413's 16 weeks, every peer compresses or defers something

The pacing comparison below aligns the closest schedule-published courses against CSC 413's weekly arc. Two patterns stand out. First, on topic ordering, CSC 413 is alone in placing a design-quality block (cohesion/coupling/SOLID in week 6, refactoring/smells in week 7, UML in week 8) *before* design patterns; SJSU and Northeastern teach patterns by week 4–6 and never return to refactoring, while CMU interleaves patterns (week ~5–6) and refactoring (~week 7) much like CSC 413 but reaches testing earlier. Second, on project pacing, CSC 413 and EPFL are the only two that keep a milestone due essentially every week from week 1–2 onward; CMU's milestones are biweekly multi-part homeworks, SJSU's project occupies only weeks 7–16, and Northeastern's main project occupies only the back half.

The topic-coverage ledger is equally asymmetric. Universal across serious peers: OO principles, UML (except MIT/UW), some named patterns, unit testing, exceptions. CSC 413 topics essentially unique in the surveyed set: **SOLID taught as a named five-principle framework** (only SJSU also names it; CMU covers the ideas under design-for-change), **code smells and technical debt as named units** (UBC alone names refactoring; nobody names smells or debt), **MVC as an explicit architecture week** (implicit in peers' GUI weeks; explicit only in the Alberta MOOC and Northeastern's lectures), and **build tooling (Maven) as taught content** — Maven appears in no peer syllabus reviewed anywhere ([peer notes](https://www.sjsu.edu/cs/docs/syllabi/fall26/CS_151_Fall_2026_Telvin_Zhong_Syllabus.pdf); [CMU s2026](https://cmu-17-214.github.io/s2026/)). Conversely, the block CSC 413 deliberately omits — concurrency/threads plus GUI frameworks — is core at CMU (4–5 lectures), SJSU, MIT, and EPFL (JavaFX stages). That is a defensible trade, but it is the one gap a transfer student or ABET-style reviewer would notice first.

## Conclusion

Two findings matter beyond the catalog. First, CSC 413 occupies a niche that is emptying rather than crowding: Stanford let its Java OO-design course go dormant, MIT and UW left Java and design-pattern pedagogy entirely, and CMU — the last flagship teaching this material in Java — is rebuilding its course around agentic AI development in Fall 2026, whose assignment set ("Refactor and Critique an Unfamiliar Codebase," design-for-verification) suggests where a future CSC 413 revision could look. The borrowable mechanics from the true peers are concrete: EPFL's split of project credit between weekly autograded checkpoints and two human code-reviewed consolidated submissions (a model for balancing the perft harness against holistic design grading), MIT's alpha → code review → beta resubmission cycle, Northeastern's next-day written self-evaluations, and its extend-someone-else's-code capstone.

Second, the chess-engine structure itself appears to be genuinely novel in the published record: no peer course anchors on chess, none uses 14 milestones (peers use 2–6), none uses perft counts as an autogradable correctness oracle, and the SIGCSE/ITiCSE literature search found no paper on a semester-long chess-engine project for OO design — the nearest neighbor is a 2025 paper on tile-based games for OOP learning ([SciTePress](https://scitepress.org/publishedPapers/2025/133461/pdf/index.html)). The design is a strong candidate for a SIGCSE experience report, which would simultaneously document the course's distinctiveness and give it the citable public anchor that CMU, MIT, and EPFL already enjoy.
