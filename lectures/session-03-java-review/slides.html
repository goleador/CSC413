Question 2

How should two positions compare?

A prediction

Position a = new Position(4, 1);   // e2
Position b = new Position(4, 1);   // e2

a.equals(b);      // true or false?
§2. Take votes — hands up. Half the room is confidently wrong, and the split is the lesson. Then: "it depends" — on how Position is declared.

The obvious first draft

// first draft — not what we ship
class Position {
    int file, rank;
    Position(int file, int rank) { this.file = file; this.rank = rank; }
}

Says nothing about equals → inherits the default: is this literally the same object?

The same square, twice — and Java says false.

Label it out loud every time: "first draft — not what we ship." One example all lecture: Position, from failing draft to shipped record.

What that does to collections

Set<Position> attacked = new HashSet<>();
attacked.add(new Position(4, 1));
attacked.contains(new Position(4, 1));    // false

Map<Position, String> board = new HashMap<>();
board.put(new Position(4, 1), "white pawn");
board.get(new Position(4, 1));            // null

You put the pawn on e2 — and the board cannot find it.

Demo live, scratch file: draft class, Set, then Map. The board.get null is the one that shocks — they trust maps.

Why the engine cares

if (move.to().equals(target)) { ... }   // week 7: does a piece attack this square?
  • Every check-detection question bottoms out in a comparison
  • Get it wrong: nothing throws — the king is reported safe when he is not
equals and hashCode travel together.

Question 3

What tool does Java give us?

Before Java 16 — fixing it by hand

class Position {
    private final int file;
    private final int rank;
    Position(int file, int rank) { ... }
    int file() { ... }
    int rank() { ... }
    @Override public boolean equals(Object o) { ... }
    @Override public int hashCode() { ... }
    @Override public String toString() { ... }
}

~40 lines of boilerplate, per value type, every time.

After

public record Position(int file, int rank) { }

One line — exactly how the real class is declared.

Rerun §2: equals → true · contains → true · get → "white pawn"

The pawn is back on e2.

Delete the draft's body, change the declaration, rerun everything live. The designers watched this boilerplate written thousands of times and added "this type is just a value".

What that one line generates

Fields (private final), constructor, file() / rank(), equals, hashCode, toString.

  • Accessors have no get prefix
  • Final fields → a Position cannot change
  • Think "new value", not "new object" — nobody fears a second 3
§3. Immutability: what you hand to a method cannot come back changed; a key cannot mutate inside a map. The rule twice over: wrong equality impossible, corruption impossible.

Question 4

How do we keep invalid squares out?

new Position(99, -4) — now what?

  1. Store it and hope — the failure surfaces three classes away
  2. Refuse to construct it — it either exists and is valid, or it never existed

Take the second. Make the invalid Position impossible.

The compact constructor

public Position {
    if (!isOnBoard(file, rank)) {
        throw new IllegalArgumentException(
                "Position off board: file=" + file + ", rank=" + rank);
    }
}
  • Runs before the field assignments — cannot be bypassed
  • Message carries the values: file=8 points at the off-by-one
  • No other class ever asks "is this valid?" — if you hold one, it is
§4. IllegalArgumentException, unchecked: signals a bug, not a condition to recover from — one sentence, move on. isOnBoard and parse are static: they must answer before any instance exists.

Question 5

What happens at the edge of the board?

A knight on a1 looks two files left

/** The position offset by the given deltas,
    or null if that lands off the board. */
public Position offsetOrNull(int fileDelta, int rankDelta)

Body: yours, in M0b — three lines, built from isOnBoard.

  • new Position(8, 3) asserts — wrong assertion = bug = throw
  • offsetOrNull(2, 1) asks — "no" is a legitimate answer = null
The name carries the contract: offsetOrNull, not offset.
§5. Not an exception: eight offsets per knight, most leave the board near an edge — a normal outcome of asking about a neighbour.

Question 6

System.out.println(somePosition)

Generated: Position[file=4, rank=1] — accurate, useless on a board.

@Override
public String toString() {

A chess player says e2 — so that is what it says.

Question 7

How do we represent the two sides?

The options that compile

boolean isWhite;          // what does false mean, and whose turn is it?
int color;                // 0? 1? -1?
String color = "white";   // "White"? "WHITE"? " white"?

All three admit meaningless values. Chess has two sides, forever:

public enum Color { WHITE, BLACK }

Color.PURPLE no longer compiles.

Which way do this side's pawns move?

// without — repeated wherever pawns appear:
int direction = (color == Color.WHITE) ? 1 : -1;

// with:
Position ahead = from.offsetOrNull(0, color.pawnDirection());

Which one reads like English?

The four method bodies: yours, in M0b.

§7. The question is about a color, so the answer lives IN Color: opposite, pawnDirection, pawnStartRank, promotionRank. Behaviour belongs with the data it depends on — week 6, at its smallest.

Question 8

What do file and rank actually store?

Five candidates — thumbs up or down?

CandidateWhat it is
"e4"a String
28one index, 0–63
(4, 3)two ints, file then rank, 0-based
(3, 4)two ints, rank then file, 0-based
(5, 4)two ints, file then rank, 1-based

Must support: compare · collect · offset · print

§8, collaborative — thumbs per candidate, defend, pros and cons on the board BEFORE you evaluate. The 0–63 index is the productive one: someone always likes it, until a4 − 1 == h3. Protect the 12 minutes — first real design problem of the course.

The result

Rank 8 at the TOP holds index 7; rank 1 at the bottom holds index 0. The board prints in the opposite order to the array — that reversal is where the off-by-ones come from.

e2 = new Position(4, 1)

  • Two ints — offsets are addition, edges are a bounds check
  • 0-based — the board is an array; no - 1 on every access
  • File first — e2 is letter-first; match the domain
Neither convention is "correct." What matters: one choice, whole codebase, written down.
